# MHXX お守り乱数計算機 (Android版)

モンスターハンターダブルクロスの「お守り」の乱数を、既存の解析ロジック
(ノートブック由来、`mhxx_rng.py`) をもとに検索・予測するための、
スマホで使える純粋な計算ツールです。

**このアプリが行うこと**: フレーム番号やスキル条件から、狙ったお守りが
出るフレームを計算する — それだけです。Switch本体やゲームプロセスへの
自動入力・自動操作・通信は一切行いません(必要な数値は自分の目で見て
手入力する前提の、電卓のようなツールです)。

## 機能

| タブ | 内容 |
|---|---|
| 🔍 検索 | スキル/スロット条件を指定してフレームを検索 (完全一致 / 以上) |
| 📋 周辺確認 | 指定フレーム前後のお守りを一覧表示 |
| 🧪 調合スナイプ | 調合の「累計作成数」列から現在フレームを特定 |
| 🎯 狙い目 | クエスト/マカフシギ/天運の有効フレームを計算 |
| 📷 鑑定読取 | 鑑定結果の写真 (またはテキスト直接入力) からスキル/スロットを読み取り、検索タブへ反映 |

検索結果のカードをタップすると、そのフレームを周辺確認タブに渡して
自動表示します。

### 📷 鑑定読取タブについて

写真 (またはギャラリー画像・手入力テキスト) からお守りのスキル名・Pt・
スロットを推定し、「検索」タブの条件欄に自動入力する機能です。

- **Switch本体とは一切通信しません。** 処理対象は、ユーザーが撮影/選択
  した1枚の画像、または直接入力した1件のテキストだけです。自動操作・
  連続実行の要素はありません。
- OCRエンジンはGoogleの [ML Kit](https://developers.google.com/ml-kit)
  (日本語テキスト認識) を端末上でオンデバイス実行します。無料・APIキー
  不要・外部送信なしです。
- 認識結果は「信頼度」付きの候補として表示されるだけで、自動的に検索が
  実行されることはありません。内容を確認し「検索タブへ反映」を押した
  あとも、検索タブ側で自由に修正できます。
- カメラ/ギャラリー機能が使えない端末では、テキスト欄に直接入力・貼り
  付けするだけでも同じ解析ロジックが使えます。

**⚠️ 検証状況について**: この機能のうち、写真から文字を読み取る
「解析ロジック」部分 (`ocr/skill_matcher.py`) は本プロジェクト内で
2,000件以上のテスト用データを使って動作確認済みです。一方、カメラ撮影
とAndroidのML Kit本体を呼び出す部分 (`ocr/android_ocr.py`) は、
Android実機がないこのビルド環境では動作確認ができていません。
実機で調整が必要になる可能性があります (下記トラブルシューティング
参照)。

## セットアップ (GitHub Actionsで APK をビルド)

1. GitHubで新しいリポジトリを作成します (Public / Private どちらでも可)。
2. このフォルダの中身をそのリポジトリに push します。

   ```bash
   cd mhxx_rng_app
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<あなたのユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```

3. push すると `.github/workflows/build-apk.yml` が自動的に動き、
   Buildozer で APK をビルドします。GitHubの対象リポジトリで
   **Actions** タブを開くと進行状況が確認できます。
   (手動で再実行したい場合は Actions タブ →
   「Build APK」→ **Run workflow** でも起動できます)
4. ビルドが終わったら、そのワークフロー実行画面の一番下
   **Artifacts** から `mhxx-rng-tool-apk` をダウンロードします
   (zipでダウンロードされるので展開すると `.apk` が入っています)。
5. スマホにその `.apk` を転送し、タップしてインストールします。
   初回は「提供元不明のアプリ」の許可を求められることがあります。

### 注意

- **初回ビルドは20〜40分程度かかります** (Android SDK/NDKを
  ダウンロードするため)。2回目以降はキャッシュが効いて
  短縮されます。
- これは個人利用向けのツールとして構成しています。Google Play
  で公開する場合は `buildozer.spec` の `package.domain` を
  実際に所有するドメインの逆順にするなど、別途調整が必要です。
- 「検索」を大きいステップ数 (数千万〜) で実行すると、端末や
  他の作業状況によっては「停止」を押してから実際に止まるまで
  数秒かかることがあります (バックグラウンドスレッドが現在の
  処理を終えてから停止するため)。
- 鑑定読取タブのカメラ/ギャラリー機能は `CAMERA` /
  `READ_MEDIA_IMAGES` 権限を使います。初回起動時に許可を求められます。

### 🔧 鑑定読取(OCR)がうまく動かないときは

前述の通り、カメラ撮影とML Kit呼び出し部分は実機未検証です。
このため、現在の `buildozer.spec` では **ML Kit連携をデフォルトで
無効化(コメントアウト)**しています。この状態でも:

- ✅ 検索/周辺確認/調合スナイプ/狙い目タブは通常通り動作します
- ✅ 鑑定読取タブの「テキスト直接入力→解析」は動作します
- ❌ 鑑定読取タブの「写真から自動でテキストを読み取る」機能のみ
  使えません (エラーメッセージが表示され、手動入力を促します)

ビルドが通ることを確認できたら、`buildozer.spec` の以下2行の
先頭の `#` を外して再度pushすると、カメラからの自動OCRも試せます。
それでもビルドエラーが出る場合は、以下を確認してください。

```
android.gradle_dependencies = com.google.mlkit:text-recognition-japanese:16.0.1
android.enable_androidx = True
```

- **ビルドエラーになる場合**: `android.gradle_dependencies` の指定が
  効かない buildozer のバージョンがまれにあります。バージョン番号を
  最新に上げて試すか、コメントアウトしたままお使いください。
- **アプリ起動時にクラッシュする場合**: `android.enable_androidx` が
  効いていない、または `com.google.mlkit:text-recognition-japanese`
  のバージョンが古い可能性があります。バージョン番号を最新に
  上げて再ビルドしてみてください。
- **カメラ撮影後に画像が渡ってこない場合**: Android 7 (API24) 以降は
  file:// URIを直接渡せないFileProvider絡みの制約があることが
  知られています。plyerのバージョンを最新にする、またはギャラリー
  選択やテキスト直接入力を代わりに使ってください。
- いずれの場合も、**テキスト直接入力は上記の問題と無関係に動作します**
  (Android依存の部分を一切経由しないため)。写真からの自動入力が
  うまくいかない場合の実用的な代替手段としてお使いください。

### 🔧 ビルドエラー「grpmodule.c」「setgrent」「getgrent」が出る場合

これは上記のOCR関連設定とは無関係の、CPython自体をAndroid向けに
クロスビルドする際の[既知の上流バグ](https://github.com/python/cpython/issues/114875)です。
Androidの標準Cライブラリ(Bionic)には Unix的なグループデータベース
関数 (`getgrent`/`setgrent`/`endgrent`) が無いにもかかわらず、CPython
の `configure` スクリプトが `grp` モジュールをビルドしようとして
失敗します。このアプリのコード自体は `grp` モジュールを一切使用して
いません。

`patches/android-config.site` と、ワークフロー内の `CONFIG_SITE`
環境変数指定で、この `grp` モジュールのビルドをスキップさせる対処を
あらかじめ入れてあります (autoconfの標準機構を使っているので、
python3以外のレシピには影響しません)。

**この対処が効かず同じエラーが再発する場合**、またはこれ以外のビルド
エラーが出る場合は、お手数ですが最新のログ (「Build with Buildozer」
ステップの「Search logs」で `error:` を検索した箇所) を教えてください。


Android実機にインストールする前に、PC上のKivyで見た目を
確認することもできます。

```bash
pip install kivy
python main.py
```

カメラ/ギャラリー機能 (`plyer`) が未インストールでもアプリ自体は
起動します。その場合、鑑定読取タブは自動的にテキスト直接入力のみの
状態になります (`pip install plyer` で有効化できますが、実際のカメラ
撮影はAndroid実機でのみ動作します)。

## 技術的な補足

- `mhxx_rng.py` は元のデスクトップ版ツールのロジックを**一切変更せず
  そのまま**使用しています。乱数アルゴリズム・テーブル・しきい値の
  正しさは元のロジックにそのまま依存します。
- `ocr/skill_matcher.py` (OCRテキスト→スキル/スロット推定ロジック) は
  Switch/Android非依存の純粋なテキスト処理で、4種類のお守り×2,000件
  超のランダム生成データで動作確認済みです。同名スキルがスキル1/
  スキル2両方の候補に存在するケース (例: 光るお守りの「毒」) も
  正しく区別します。
- `ocr/android_ocr.py` (Android ML Kit連携) は実機未検証です。上記の
  トラブルシューティング項目を参照してください。
- 日本語表示のため [Noto Sans JP](https://github.com/notofonts/noto-cjk)
  (SIL Open Font License 1.1) を同梱しています。ライセンス全文は
  `assets/fonts/LICENSE-NotoSansJP.txt` を参照してください。
- UIはタッチ操作向けに新規に作成したものです (Kivy)。検索は
  バックグラウンドスレッドで実行し、進捗表示・途中停止に対応して
  います。
